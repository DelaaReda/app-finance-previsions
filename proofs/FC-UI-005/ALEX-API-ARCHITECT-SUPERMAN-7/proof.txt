# Preuve de mise en œuvre - FC-UI-005

## Tâche: Stocks: placeholders et couleurs sûres (éviter affichage 0/100 incohérent)

## Résumé
Mise en place de l'affichage sécurisé des indicateurs techniques (SMA/RSI) avec "N/A" au lieu de "0.00" pour les valeurs manquantes/null.

## Changements apportés
- Mise à jour de `/services/stocks.service.ts` pour retourner `null` au lieu de `0` pour les indicateurs manquants
- Création de deux nouvelles fonctions utilitaires dans `/utils/safeAccess.ts`:
  - `safeFormatNumber(value, decimals)` - formate les valeurs numériques avec "N/A" pour null/undefined
  - `getSafeRSIColor(rsi)` - calcule les couleurs RSI avec gestion de valeurs null
- Mise à jour de `/pages/Stocks.tsx` pour utiliser ces helpers au lieu de `.toFixed()` direct

## Structure mise en place
- Les indicateurs techniques retournent `null` si absence au lieu de `0` 
- `safeFormatNumber()` gère les conversions sécurisées avec "N/A" fallback
- `getSafeRSIColor()` détermine les couleurs avec sécurité sur valeurs null
- Protection complète contre l'affichage de "0.00" pour indicateurs réellement manquants

## Fichiers modifiés
- `frontend/webapp/src/utils/safeAccess.ts` - Ajout fonctions formatage sécurisé
- `frontend/webapp/src/services/stocks.service.ts` - Changement fallbacks à null
- `frontend/webapp/src/pages/Stocks.tsx` - Utilisation des helpers sécurisés

## Vérification
- Lorsque SMA/RSI sont null, affichage "N/A" au lieu de "0.00"
- Les couleurs restent cohérentes (gris pour N/A, rouge/vert pour valeurs valides)
- Aucune erreur de type "Cannot read property 'toFixed' of null"
- L'UI reste lisible et sans crash lors de valeurs manquantes

## Résultats
- Affichage "N/A" pour valeurs manquantes: ✅
- Affichage de valeurs réelles: ✅ (formatage normal avec .toFixed())
- Gestion sécurisée des nulls: ✅ (pas de crash)
- Cohérence couleur: ✅ (couleurs appropriées selon disponibilité)
- Utilisation helpers: ✅ (safeFormatNumber, getSafeRSIColor)
