# Preuve de mise en œuvre - FC-UI-003

## Tâche: Toggle "include_signals=1" (heavy path) sur Dashboard

## Résumé
Ajout d'un toggle dans Dashboard.tsx permettant à l'utilisateur d'activer le mode lourd côté API qui inclut les signaux détaillés.

## Changements apportés
- Ajout d'un nouvel état `includeSignals` dans le composant Dashboard
- Mise à jour de la logique de requête pour inclure le paramètre `include_signals` quand le toggle est activé
- Ajout d'un switch UI dans la section des filtres pour permettre à l'utilisateur d'activer/désactiver le mode lourd
- Mise en place de la protection de l'interface durant les appels de rafraîchissement
- Mise à jour de la section des filtres actifs pour inclure l'indication du mode détaillé

## Fichiers modifiés
- `frontend/webapp/src/pages/Dashboard.tsx` - Ajout toggle, logique requête, UI

## Vérification
- Le toggle est fonctionnel et change le comportement de l'API
- Le paramètre `include_signals=1` est envoyé à l'API quand le mode est activé
- L'UI met à jour les indications de filtres actifs
- L'interface est désactivée pendant les appels de rafraîchissement pour éviter les appels multiples

## Résultats
- Toggle fonctionnel: ✅ 
- Paramètre API: ✅ (include_signals=1 quand activé)
- UI mise à jour: ✅ (indication du mode dans filtres actifs)
- Protection des appels: ✅ (disable pendant isFetching)
