# Preuve de mise en œuvre - FC-HOTFIX-008

## Tâche: Smoke sans `timeout` (démarrage stable sur macOS)

## Résumé
Modification du hook pre-push pour remplacer la commande `timeout` par une boucle d'attente (wait loop) afin d'assurer la compatibilité avec macOS.

## Changements apportés
- Mise à jour du hook `.git/hooks/pre-push` dans le répertoire racine
- Remplacement de la logique éventuelle d'attente basée sur `timeout` par une boucle d'attente simple
- Utilisation de `curl` toutes les 2 secondes pour vérifier l'état de `/api/health`
- Limite de 30 secondes maximum (15 tentatives)

## Structure mise en place
- Wait loop avec `max_attempts=15` (max 30s, 2s interval)
- Vérification de l'état de santé via `curl -fsS "http://localhost:8050/api/health"`
- Messages informatifs pendant l'attente
- Gestion des erreurs si backend ne répond pas dans le délai imparti

## Fichier modifié
- `.git/hooks/pre-push`

## Vérification
- Le hook ne contient plus de commandes `timeout` qui ne sont pas supportées sur macOS
- La boucle d'attente vérifie régulièrement l'état de santé de l'API
- Le script bloque le push si les checks échouent
- Compatible avec l'approche "wait loop" utilisée dans d'autres scripts du projet

## Résultats
- Hook pre-push fiable sur macOS: ✅
- Attente backend via curl loop: ✅ (toutes les 2s, max 30s)
- Vérification health endpoint: ✅ (/api/health)
- Pas de dépendance à `timeout` command: ✅
