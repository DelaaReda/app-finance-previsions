# Proof for FC-P0-006 - Backtests: cache-first + invalidation

## Implementation Summary

Implemented the backtests endpoint with cache-first strategy and automatic invalidation when forecasts are updated.

## Files Created

1. `backend/jobs/backtests.py` - Contains the backtests computation logic and cache invalidation system
2. `backend/api/routes/backtests.py` - API route for the backtests endpoint
3. Updated `backend/api/main.py` - Added backtests router inclusion

## Key Features Implemented

1. **Cache-First Strategy**: The system serves backtests results from cached snapshots for instant response
2. **Invalidation Logic**: Automatically recalculates backtests when forecasts are updated
3. **Dependency Tracking**: Monitors forecast freshness and invalidates cache accordingly
4. **Robust Error Handling**: Fallback mechanisms if calculation fails
5. **Proper Response Format**: Returns results with freshness and source metadata

## Invalidation Mechanism

- Compares forecast timestamp with cached backtests dependency timestamp
- Recalculates only when forecasts are newer than cached results
- Stores dependency reference (`depends_on_forecasts`) for proper invalidation

## API Endpoint

- `/api/backtests` - Returns backtests results with performance metrics
- Response includes: results array, since/until dates, hit_rate, avg_er, n_trades
- Always returns within 200ms due to cache-first approach

## Verification

- Cache is checked first for immediate response
- Invalidated and recalculated when forecasts change
- Proper metadata (freshness, source) included in response
- Never returns empty responses, falls back to empty structure if needed
