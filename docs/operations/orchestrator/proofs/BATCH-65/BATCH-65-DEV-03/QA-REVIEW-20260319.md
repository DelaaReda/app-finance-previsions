## Summary

The fix applied to `apps/web/src/domains/forecasts/pages/app.js` correctly resolves the hero brief rendering issue where the landing page showed "No brief available yet. Check back soon!" when the backend returned only the nested starter contract.

## Root Cause

The `loadAndRenderHeroBrief()` function was reading hero content from raw top-level `brief_of_day` / `daily_brief` fields instead of the already-normalized shared starter state. When the backend returned only the nested starter contract (`copilot_start.brief_of_day`), the raw top-level fields were missing.

## Fix Applied

Updated `apps/web/src/domains/forecasts/pages/app.js` (lines 9139-9148):

```javascript
const sanitizedStart = sanitizeCopilotStart(
  (data && typeof data === 'object' && (data.copilot_start || data.copilotStart))
  || data
);
const starterState = buildCopilotStartState({
  ...(data && typeof data === 'object' ? data : {}),
  copilot_start: sanitizedStart,
});
const brief = starterState && typeof starterState === 'object' && starterState.brief
  ? starterState.brief
  : {};
```

The fix:
1. Reuses existing `buildCopilotStartState`/`sanitizeCopilotStart` flow (no new helpers)
2. Renders summary, signals, risks, freshness, and sentiment from `starterState.brief`
3. Accepts both camelCase and snake_case brief fields through the sanitizer
