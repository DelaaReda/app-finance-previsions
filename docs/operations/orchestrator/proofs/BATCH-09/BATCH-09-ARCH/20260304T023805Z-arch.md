# BATCH-09-ARCH — Alerting architecture execution map

Date: 2026-03-04T03:00:00Z
Owner: planner

## Architecture target
- Source unique d'état orchestration/monitor: `docs/operations/orchestrator/*` + runtime health scripts.
- Pipeline alerting: détection -> normalisation -> sévérité -> déduplication -> exposition API/monitor.
- Contrat de preuve: tout correctif incident doit fournir `root_cause`, `fix_applied`, `verify(before/after/test)`.

## Reuse-first map (INTEGRATION-APP-EENGINEER-RECOMMENDATIONS)
- Backend orchestration/health: `scripts/fc_health_check.sh`, `scripts/monitor_agents.sh`, `scripts/health_snapshot.sh`.
- Monitor API aggregation: `apps/monitor/server.py`.
- Runtime contract parsing: `platform/automation/cron_tmux_role_runner.sh`.
- Debug assist: `scripts/agent_deep_troubleshoot.sh`.

## Implementation tracks
### DEV-01 (backend/contracts)
- Standardiser alert payload (severity, category, source, ts, blocker, impact).
- Introduire contrat de logs d'erreur colorisables (level/error_type/source).
- Garantir compatibilité monitor API sans casser endpoints existants.

### DEV-02 (UI monitor)
- Afficher exécutions récentes réellement utiles (task_update, root_cause, fix, verify).
- Coloriser logs par niveau (`ERROR/WARN/INFO/ACTION`) avec contraste stable.
- Supprimer rôles obsolètes de l’UI et garder mapping dynamique sur rôles actifs.

### DEV-03 (integration + QA)
- Smokes de cohérence monitor: data réelle queue/workboard/ticks.
- Test non-régression sur incidents complexes: stale locks, session mismatch, batch-id parsing.
- Preuve avant/après sur un incident réel reproduit.

## Gates et preuves obligatoires
- Gate A (contract): clés obligatoires présentes et cohérentes dans exécution récente.
- Gate B (runtime): monitor reflète l'état réel (same counts/states queue/workboard).
- Gate C (quality): au moins 1 scénario incident reproduit puis corrigé avec preuve before/after/test.
