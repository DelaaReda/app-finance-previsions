## Objectif
Implémenter le gate GO/NO-GO du MVP avec vérification des coûts runtime et rollback testable.

## Scope BATCH-10
1. **BATCH-10-ANALYSIS**: Audit coûts runtime actuels (API calls, tokens, cron overhead)
2. **BATCH-10-ARCH**: Définir la structure du release gate et ses critères
3. **BATCH-10-DEV-01**: Implémenter les checks coût dans le pipeline tick
4. **BATCH-10-DEV-02**: Ajouter le gate GO/NO-GO dans fc_agent_tick.sh
5. **BATCH-10-DEV-03**: Dashboard monitor — afficher métriques coût en temps réel
6. **BATCH-10-ADMIN-01**: Valider le gate en conditions réelles
7. **BATCH-10-GOV-REVIEW**: Gate final PASS/BLOCKED

## Critères de succès
- Les coûts par tick sont mesurés et loggués (tokens, temps, fréquence)
- Un gate bloque automatiquement les ticks si seuil dépassé
- Le rollback est documenté et testable en < 2min
- Le dashboard affiche le coût moyen des 24 dernières heures

## Architecture
- Pas de nouveau module: enrichir `fc_agent_tick.sh` + `health_snapshot.sh`
- Gate configurable via `FC_COST_GATE_*` env vars
- Logs coût dans `logs-codex-runs/fc-ticks/cost.log`
